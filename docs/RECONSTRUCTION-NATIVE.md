# Reconstructing the current native components

Running the released components needs no Cargo access. Use the [download helper](DOWNLOAD-KIT.md), extract the matching native ZIP and separate WASM ZIP with approved OS tools, and follow [host integration](HOST-INTEGRATION.md). Their exact archives retain their original source/worker/SDK identities. The complete source4 handoff includes all later reconstruction code; the engine baseline used to produce the current runtimes remains source3-r1.

There are two developer workflows. To compile from Rust source without a registry, use the four vendor captures, complete3 support and matching pinned tools with the [offline recipe](engines/OFFLINE-BUILD.md). This needs the approved native linker/OS SDK, existing Node and system tar. Python and an Actions token are not prerequisites for that Rust recipe.

To reassemble the three exact current native ZIPs from their original compiled CI outputs, use the public workflow **Exact source3 native reconstruction and immutable publication**. Leave its publish input false for verification. It restores the complete source3 TAR, support, all original native CI ZIPs and captured provenance through the fixed records in scripts/ci/source3-cloud-publisher/inputs.json. The Mac and static Windows restore mappings are config/macos-source3-ci-restore-progress3.json and config/windows-source3-static-ci-restore-progress3.json. All44 fixed reconstruction data records have complete public readback in [run42402918764](https://github.com/Mohammed-Moniem/embedded-office-suite/actions/runs/42402918764).

The cloud launcher scripts/ci/source3-cloud-publisher/launch.mjs requires the exact reviewed driver, six compressor files and fixed environment before restoring anything. The workflow checks the source hashes before exposing its job token. It admits macOS ARM64, Node24.18.0, the measured system libz1.2.12 at /usr/lib/libz.1.dylib and the existing /usr/bin/python3. Its explicit raw-DEFLATE stream reproduces the original local packager profile; official Node24.18.0 bundles a different zlib version. This narrow cloud-only encoder is not installed globally or required by the corporate runtime/offline Rust recipe. Unsupported environments and altered dependencies fail.

Each resulting native ZIP must still match its original full byte size/SHA before any release publication. Exact source manifests, worker hashes, SDK, permissions and original asset notices remain mandatory. The unchanged output acceptance is335d5ab9… for macOS ARM64, a9ad54c1… for Intel and055a2744… for Windows. The complete hashes are in config/native-progress3.json. Existing release names are never overwritten. Full hosted reconstruction with the explicit encoder is recorded separately from the [prepared-code review](verification/source3-compression-review1.json); its small local equivalence tests alone do not prove all three full archives.

The earlier HTTP415 run and the later same-payload/different-container run remain failed evidence. Neither changed accepted archive hashes. Actual runtime operation is separately established by the [native/data review](verification/source3-public-native-data-review1.json) and [durable receipt replay](verification/public-native-data-source3-durable.json); reconstruction success alone does not grant runtime, Windows11, private-host, optional-feature or Microsoft/Adobe parity acceptance.
