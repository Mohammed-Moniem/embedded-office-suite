# Current personal Office components

Status: **IN_PROGRESS**. Source and progress releases are in the independent repositories [WordCraft](https://github.com/Mohammed-Moniem/wordcraft), [PdfCraft](https://github.com/Mohammed-Moniem/pdfcraft), [DeckCraft](https://github.com/Mohammed-Moniem/deckcraft) and [GridCraft](https://github.com/Mohammed-Moniem/gridcraft). Shared SDKs, WASM editors, baseline platform packages and offline build inputs are in [embedded-office-suite](https://github.com/Mohammed-Moniem/embedded-office-suite).

The current standalone CLI packages below run on Apple Silicon macOS without Cargo or a Rust installation. Keep each extracted directory intact, including its data and legal files; follow its packaged README and run `bin/<component>-cli --help` from that directory. These are unsigned debug CLI progress components. The native desktop workers and WASM editors for the existing Node/WebView host are separate baseline packages described below.

## Existing multi-platform SDK and WASM baseline

For the existing approved Node/WebView desktop host, use the [baseline integration guide](https://github.com/Mohammed-Moniem/embedded-office-suite/blob/main/START-HERE.md), [component inventory](https://github.com/Mohammed-Moniem/embedded-office-suite/releases/download/v0.1.0-progress.4/COMPONENT-DOWNLOADS.md) and [standalone download helper](https://github.com/Mohammed-Moniem/embedded-office-suite/releases/download/v0.1.0-progress.3/office-kit-downloader-progress3-r2.zip). The runtime profile collects the target's native ZIP and the four-editor WASM/SDK ZIP; the all profile also collects the source3 baseline, four vendor archives, support data and matching Rust tools. The helper verifies sizes and full SHA-256 values, including offline transfer verification. It does not install or extract files.

These baseline native packages were exercised on Windows Server 2022 x64, macOS ARM64 and a real Intel Mac. The WASM/SDK baseline was exercised on macOS ARM64 Chromium. They retain their own older source identities. The new standalone CLI releases above do not replace those SDK workers or establish equivalent results on those other platforms. Windows Server 2022 evidence does not establish Windows 11 acceptance.

## Source and offline rebuilding

The shared [complete source4 handoff](https://github.com/Mohammed-Moniem/embedded-office-suite/releases/download/v0.1.0-progress.4/office-source-progress4-r1.tar.gz) includes the earlier complete suite, engine baseline, CI, reconstruction and download tools. Its [checksum](https://github.com/Mohammed-Moniem/embedded-office-suite/releases/download/v0.1.0-progress.4/office-source-progress4-r1.tar.gz.sha256) identifies that immutable handoff. Use the per-component source archives above for the later scoped changes. The shared repository's automatic GitHub source ZIP omits engine trees.

The captured rebuild tools are Rust/Cargo 1.95.0, Trunk 0.22.1, wasm-bindgen 0.2.129 and Binaryen 131. See the [offline recipe](https://github.com/Mohammed-Moniem/embedded-office-suite/blob/main/docs/engines/OFFLINE-BUILD.md) and [build guide](https://github.com/Mohammed-Moniem/embedded-office-suite/blob/main/docs/BUILDING.md). An approved target linker and OS SDK are still required for rebuilding; the runtime packages themselves need no Cargo registry access. Complete offline reconstruction of the latest four source versions on every corporate target remains in progress.

The private desktop host has not been integrated or tested here. Microsoft Office/Acrobat feature parity, broad document security/fidelity, current Windows 11/Intel/GUI/WASM qualification and complete all-PR/all-issue implementation remain unfinished. The [official feature comparison](https://github.com/Mohammed-Moniem/embedded-office-suite/blob/main/docs/FEATURE-COMPARISON.md) covers selected workflows and is not a whole-product equivalence claim.
