# Node adapter verification

Status: implemented integration foundation; full suite acceptance remains in progress.

Observed on the development macOS ARM64 machine using installed Node and TypeScript:

- 49 tests pass, zero failures, across `test/stdio.test.mjs`, `test/integration.test.mjs`, `test/host.test.mjs`, and `test/lifetime.test.mjs`.
- Type declarations pass `tsc --noEmit --strict --lib es2022,dom --module nodenext --moduleResolution nodenext packages/node/index.d.ts`.
- Tests use real Node child processes with a clearly labelled synthetic MCP peer. They verify initialization, supported protocol versions, tool requests, fragmented UTF-8/CRLF, errors, stderr separation, invalid/duplicate/uncorrelated/oversized replies, pending/outgoing limits, cancellation, initialization/request timeouts, spawn failure, process exits and teardown.
- Facade checks cover all four pinned MCP mappings against that peer, session isolation, host effect authorization, lifecycle command refusal, stale native/live revisions, host read/write ownership, failed-save retry, edits during save, ordered save snapshots, bounded tool discovery, namespaced dispatch, and rejected legacy browser sessions.
- Filesystem tests verify read/write grant separation, lexical/canonical symlink boundaries, sibling prefix rejection, bounded input files, atomic replacement, cancellation before commit and temporary-file cleanup.

Contracts inspected at the pinned revisions from `config/upstreams.json`: all four `docs/mcp.md`; Word/Deck/Grid `crates/mcp/src/tools.rs`; PDF `crates/automation/src/tools.rs` and `crates/automation/README.md`. Engine tool availability is checked again through actual MCP discovery at runtime.

Independent review finding F2/R2 is repaired: stdio request cancellation and one total deadline now cover a pending initialization handshake. Four added process regressions exercise a short caller deadline against a silent initializer, cancellation that tears down other waiting callers, a deadline spanning delayed initialization and a hanging request, and an already-aborted caller that leaves initialization usable. In the observed run these settled at about 32 ms, 23 ms, 506 ms, and 317 ms respectively; all passed without waiting for the separate one-second handshake timeout.

Second component review C2-01/C2-02 is repaired at the facade boundary. Fourteen lifecycle regressions now cover admission queue budgets, delayed authorization, remaining budget propagation, uncooperative host reads/writes, initialization/discovery cancellation with scratch cleanup, deferred save cancellation, close waiting on a writer, uncertain in-flight commands, bounded disposal and failed-disposal repetition. Signals and remaining budgets reach host callbacks; late host callbacks cannot dispatch later work or establish a clean acknowledgement. A writer ignoring cancellation may still commit externally, so the result remains explicitly uncertain and dirty; the actual pending writer retains ordering until it settles.

`node packages/node/test/real-lifetimes.mjs` also passed 11 checks against the actual patched Grid worker on macOS ARM64, reproducing the review's short-deadline authorization/queue/save/close probes and aborted saves/disposal. It observed no late cell edit or clean-save acknowledgement and delivered aborted derived signals to the controlled host writer. This is actual native-worker evidence with generated content and controlled host callbacks, not proof that arbitrary external storage can be forcibly interrupted.

Actual macOS ARM64 engine checks also passed after the lifetime repair via `node packages/node/test/real-engines.mjs wordcraft pdfcraft deckcraft gridcraft`: create, edit a known sample, host atomic save, close, reopen the real DOCX/PDF/PPTX/XLSX output, and extract/read the preserved sample. Word, PDF and Deck also returned actual PNG previews; Grid's headless rendering remained explicitly unsupported. The files had the expected `%PDF` / `PK` magic and were 6577 / 972 / 22640 / 4072 bytes in this run. The test only used generated sample content and removed temporary files. This baseline Grid check retained its explicit unconfined opt-in; the separate patched Grid lifetime runner selected native roots.

Important observed defect: pinned Grid's `apps/gridcraft-cli/src/main.rs` MCP parser accepts only `connect`, `in`, and `sample`; it has no root flags. The Grid check used explicit test-only `allowUnconfinedWorker:true` and reported `unconfined-host-reviewed`. Grid is disabled by default without that opt-in. This check does not establish all-four worker confinement.

The subsequent isolated Grid root patch was built and exercised on macOS ARM64 with the Node adapter selecting `filesystemPolicy:'automation-roots'`: 35 actual CLI checks passed, including host save/reopen and denied path escapes. The baseline remains blocked by default. Patch source, attribution, commands, hashes and platform limits are recorded in `patches/gridcraft/README.md` and `VERIFICATION.json`. Live close requests also carry the synchronized authoritative revision so the actual engine can reject a human edit racing the final close request.

Not established by these tests: general file-format fidelity, WASM same-session operation, an implemented revision/save engine extension, private harness integration, Windows x64 or macOS x64 runtime behavior, OS/network sandboxing, offline source rebuild completeness, Microsoft 365/Acrobat equivalence, or final release acceptance. Exact distributed-archive tests belong to the parent integration gates and must be reported separately. The live-browser test peer is synthetic and does not replace an engine qualification.
